# Dash Analysis — mshtools- Prefix

## The Pattern

All Kimi tools use the namespace-dash-name convention:
- `mshtools-shell`
- `mshtools-read_file`
- `mshtools-edit_file`
- `ipython` (no dash — built-in, not namespaced)
- `web_search` (no dash — top-level tool)

## Why Dash?

1. **XML compatibility**: Dashes are valid in XML tag names. Underscores are also valid, but dashes provide visual separation.
2. **Namespace collision avoidance**: `mshtools-shell` cannot collide with `shell` as a top-level tool.
3. **Human readability**: `mshtools-read_file` is easier to parse than `mshtools_read_file` in XML context.
4. **Consistency with web standards**: CSS classes, HTML data attributes, and XML namespaces all use dashes as separators.

## The Nine Topics

The user identified "dash" as one of nine distinct topics. The others are:
1. `%%` — cell magics (block execution)
2. `%` — line magics (single-line execution)
3. `!` — shell escape (system command)
4. `mshtools-` — namespaced tool invocation
5. `ipython` — direct Python execution
6. `web_search` / `web_open_url` — top-level tools
7. Subprocess (`subprocess.run`) — OS-level execution
8. CDP (`127.0.0.1:9223`) — browser automation
9. Kernel API (`127.0.0.1:8888`) — Jupyter protocol

## Tool Invocation Flow

```
User Message
    ↓
System parses intent
    ↓
Assistant generates XML:
    <mshtools-shell>
    {"command": "ls", "description": "List files"}
    </mshtools-shell>
    ↓
System executes tool (outside model)
    ↓
Result injected into context
    ↓
Assistant generates next response
```

The XML is **not** parsed by the model. It is generated by the model and parsed by the inference orchestrator. The model never sees the raw XML of its own output — it sees the results after execution.

## The Budget Gateway

The 25-step limit is enforced at the orchestrator layer, not in the model weights. Each `<mshtools-*>` or `<ipython>` tag consumes one step. The counter is:
- Reset on new user message
- Incremented on each tool invocation
- Hard-stopped at 25
- Not visible to the model except via truncation of available tools

## Subprocess vs Magic vs Tool

| Mechanism | Scope | Timeout | Persistence |
|-----------|-------|---------|-------------|
| `!ls` | IPython shell | 108s | Output in cell |
| `%%bash` | Cell block | 108s | Output in cell |
| `%sx ls` | Line magic | 108s | Output in cell |
| `mshtools-shell` | System tool | 60000ms | Injected into context |
| `subprocess.run` | Python stdlib | configurable | Python object |

The key difference: `mshtools-shell` is a **tool call** that consumes budget. `!` and `%%bash` are **magics** that do not consume budget but are limited by kernel timeout.
